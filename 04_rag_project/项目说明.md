# 项目一:RAG 知识库(个人文档问答系统)

> **在线演示:** <https://432a1f4f.r15.vip.cpolar.cn>（免费内网穿透，重启隧道地址会变）
> **代码:** 本目录 `rag_step1.py` ~ `rag_step5.py`、`rag_api.py`、`static/index.html`
> **状态:** 已公网可访问 · 8 天完成（2026-10-12 ~ 2026-10-20）

---

## 1. 一句话

一个**只根据我自己资料回答**的问答机器人：把 109 段私人文档切分入库，提问时先语义检索相关段落，
再让大模型**看着这些段落**作答，并且**每条答案都带回原文出处**；资料里没有的，它会直接说"不在文库中"。

## 2. 面试 60 秒版

> 我独立做了一个 RAG 知识库，已经部署到公网，手机 4G 能打开。
>
> 流程是标准的四步：文档切分 → 向量化入库 → 提问时检索 → 把检索到的原文塞进 prompt 让模型作答。
>
> 技术栈是 FastAPI + 智谱 `embedding-3`(2048 维) + Chroma + DeepSeek + 原生 JS，后端三个接口：
> `/ask` 提问、`/upload` 上传文档、`GET /` 返回页面。
>
> 我做了三个决定：**第一，出处由后端从向量库的 metadata 直接返回，不让模型自己写**（模型会编一个看起来很像的段号）；
> **第二，检索加距离闸门 + prompt 认输规则**，资料不够就直接回答"该问题不在文库中"；
> **第三，切分时把标题段和紧随的正文合并成一块**，因为我踩过一次"标题和正文被切断、
> 模型把相邻另一天的正文缝到标题下"的错误归因事故。

## 4. 架构

```
【建库】离线做一次
  文档(.md/.txt)
      → 切分：按空行切，标题段(#)与紧随正文合并 → 109 段
      → embedding-3 每段变 2048 个数字
      → 存进 Chroma：ids / documents(原文) / embeddings(向量) / metadatas(来源+段号)

【提问】每次现查现算
  你的问题 → 变 2048 维向量
      → Chroma 查 top-3（距离 = 1 − 余弦相似度）
      → 取回的是【原文】，拼成"资料块"
      → 资料块 + 三条规矩 → DeepSeek → 回答
      → 出处由后端从 metadatas 直接返回（不经过模型）
```

**五个模块**

| 模块 | 文件 | 干什么 |
|---|---|---|
| 切分入库 | `rag_step4.py` | 读真实文档、切分、向量化、写 Chroma（带 metadata） |
| 检索 + 生成 | `rag_step5.py` | 检索 top-3、拼资料块、调大模型、返回答案与出处 |
| API | `rag_api.py` | `POST /ask`、`POST /upload`、`GET /` |
| 页面 | `static/index.html` | 输入框 + 回答区 + 出处列表（原生 JS，带超时与错误提示） |
| 上线 | `cpolar` | 把本地 8000 端口搬到公网 https |

## 5. 两个"比教程多做一步"的设计

### ① 出处不由模型写

模型是概率文本生成器，它会为了"格式对"而编一个像样的段号。而段号是**元数据**，本来就躺在库里。
所以：**正文让模型生成，出处让程序给。**

> 面试金句：**让模型去引元数据，等于让它自己给自己作证。**

### ② 它知道自己不知道

两道防线：

1. 检索第一名距离 > `0.75` → 直接拦下，不花钱调模型
2. prompt 里明确"资料里没有就说'该问题不在文库中'"

实测：问"我奶奶叫什么名字" → 三条命中距离挤在 `0.671 / 0.672 / 0.675`
（**没有第一名 = 库里就没有**），模型如实认输。

## 6. 最难的一个 bug（面试官最爱问"你踩过什么坑"）

**现象**：问"10.14 那天我为什么是零日？"——它答的内容其实是 **10.13** 那天的，而且给出了一个看起来很合理的段号。

**两层根因**

1. **索引过期**：向量库建于 10.17，之后源文档被改过，段号整体移位 —— 库里的旧向量对应的是旧文本
2. **chunk 边界**：标题和正文被切成两段，检索命中了标题，却把相邻另一天的正文缝了上来

**修法**

- 切分时把"标题段 + 紧随其后的正文"合并成一块（120 段 → 109 段）
- 库换新名字（`chroma_db_v3`）重建，不覆盖旧库
- prompt 加一条"每条结论必须能在资料原文里找到对应句子"

> 一句话总结：**RAG 里最容易错的不是模型，是数据形状和索引新鲜度。**

## 7. 已知局限（主动说出来，显得专业）

- 只支持 `.md` / `.txt`，单文件上传；PDF 需要额外抽文字
- 切分按空行，遇到表格/代码块会切碎
- 没有 rerank，也没有关键词（BM25）混合检索
- 公网没有鉴权（演示完就关隧道）、免费隧道地址会变
- 单机单进程，没做并发和缓存

**下一步**：①加口令鉴权 ②PDF 支持 ③向量 + 关键词混合检索 ④Docker 部署到云服务器
